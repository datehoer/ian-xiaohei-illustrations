# 口播视频制作与复刻

适用于明确要求制作 MP4，或复刻本项目已确认洗烘店修正版的任务。只要口播稿、分镜或 PNG 时，停在相应交付层。该方案名为 `corgi-narrated-static-v1`，是本项目的制作默认值；用户的新要求优先。

## 已确认的制作方案

以下是已确认旧版。用户选择更多配图、减少角色出镜或参考咖啡馆片的效果时，读取 [密集插画试验方案](dense-illustrated-video.md)。该方向已获用户同意试做，但试片尚不等于新的成片确认；“沿用上一期”仍指已确认版本，除非用户明确指定新方案。

| 项目 | 默认做法 |
|---|---|
| 内容版本 | 共用一份来源与账本；短片约 60–90 秒，详细片约 8–10 分钟；只要求其中一版时只做该版 |
| 画幅 | 1920×1080、16:9、30 fps |
| 主角 | 已选角色；本项目为极简线描拟人柯基，身份参考与具体场景分开 |
| 配图 | 每张独立生成；图片不含口播字幕、标题、精确数字或来源文字 |
| 画面节奏 | 镜头内图片静止，直接切换镜头；场景、左图右数字、全屏账表交替，不默认推近、平移或抖动 |
| 镜头密度 | 短片约 10–16 镜；10 分钟长片约 60–80 镜、25–35 张独立图；长片通常每 5–12 秒有画面变化，复杂表格可适当多停留 |
| 文字 | 校对后的原稿独立绘制；中文选 SC/CN 字体面；标题、数据、来源和字幕各有固定区域 |
| 配音 | 自然段合成，默认 MiMo「白桦」普通话；用实际音频定时长，不靠字数强行定时 |
| 字幕 | 用本地 ASR 词时间戳对齐原稿；显示的是原稿，不直接采用识别转写中的错字 |
| 声音 | 默认清晰旁白、无背景音乐；合成器目标约 −16 LUFS |

数量是节奏参考，不要求每期机械凑满。一个镜头可以复用已有图；换图不等于给同一张图加缩放。短版提炼结论、核心条件和风险，长版解释资料、启动投入、单位贡献、年账和敏感性，不把短片循环或拉慢凑时长。

## 找到可运行项目

这个 Skill 的安装包提供配图与制作规则，视频程序在完整仓库中。先在当前项目确认以下文件存在：

```text
scripts/episode_video.py
scripts/mimo_tts.py
scripts/narrated_video.py
requirements-video.txt
economics-of-owning/SKILL.md
examples/minimal-video/short.json
```

最后一项是仅用于说明清单结构的最小示例。已确认案例及每期材料存放于仓库外，路径由项目的素材管理文档记录。仓库内的 `docs/video-v2.md` 说明程序和本次修正，`docs/video-replication.md` 说明下一期操作与保存边界。若只有单独安装的配图 Skill，先取得完整项目位置，不能声称复制一个 Skill 文件就具备 TTS 和视频合成程序。

## 每期制作

1. 沿用会话已确定的题材、市场、语言、时长和角色。新一期放在独立目录，如仓库外的 `../ian-xiaohei-video-projects/examples/video/coffee-shop/`；成片和缓存放在对应 `outputs/coffee-shop/`。
2. 对经营经济学题材，调用同仓库 `economics-of-owning`。先保存来源清单和可复算账本，再写短、长口播。搜索模型提供线索，关键说法回到原始发布页面核查；未取得实际门店数据时保留为明确假设。已知事实、假设、推导结果分开。
3. 为每个自然段建立 `blocks`，将 `text` 与 `shots` 分开。镜头写明 `scene`、`split` 或 `table`，配图路径、标题和数字也分开。参照最小示例的 v2 JSON 结构，不把 `[画面]`、`[停]` 送入 TTS。
4. 先保存整期分镜和逐图提示词，逐张生成并检查角色、肢体、设备数量与动作。使用当前环境内置图像工具；原图与修正图分别保存。再更新清单中的实际图片路径。
5. 使用现有程序依次执行 `prepare`、`align`、`render`，每一步都传本期 `--output`。先检查一小段字体、版式、角色和配音，再导出完整版本。已确认的方案不需要每期重新征求风格批准。
6. 核查成片后交付 MP4，同时保留来源、账本、原稿、分镜、图片、TTS 缓存、字幕和时间轴。记录本次实际通过的检查与用户反馈。

## 字体与字幕的可靠性

字体文件名不等于字体面：本项目的 `STHeiti Medium.ttc` 索引 0 是 Heiti TC，索引 1 才是 Heiti SC。之前「口径」的 U+5F84 字符正确，但默认字体面让它显示成地区异体字形。调用程序的 `font_index` 选择逻辑；换机器或字体后打印实际字体族名，再目检「口径、账、说、骨、直」及本期真实字幕。不要将索引 1 机械套给所有字体集合。

字幕和标题从确认稿件单独绘制，不能让图像模型重画中文。字幕位置固定，生成图片的缩放或换镜不能改变字幕字形和位置。抽查图片内没有伪文字，也要检查最终编码后的字形，不以“源字符串正确”代替视觉检查。

## 配音与时间轴

- 保存原始 TTS WAV 和请求参数指纹；密钥从环境或隐藏输入读取，不写入 Skill、JSON、脚本或归档。
- 本地识别只提供少量领域词，不把整段标准答案塞入 `initial_prompt`；否则可能漏识别开头或中间内容。原稿用于识别后的对齐。
- 检查漏读、重复、尾部额外语音和关键金额；低匹配率是检查线索，不等于音频必然错。ASR 检查不等于完成了人工试听。
- 镜头与字幕各有时间轴；一段旁白可以切多个镜头。字幕不丢字、不重叠、不越过片尾，画面覆盖全部音频。
- 局部音频裁剪绑定那段音频的缓存指纹。新一期不能继承洗烘店的 `audio_edit`、缓存指纹、固定 `tempo` 或旧的字幕时间轴。
- 只改图、字体、标题或排版时直接离线 `render`；正文或配音改变后重新 `prepare → align → render`。不为修改画面重复付费合成语音。

## 交付前验收

- 按本期账本复算年度利润、单位贡献、盈亏平衡和敏感性；短片与长片相同条件下数字一致。
- 看最终视频中的第一屏、中文密集屏、表格、换镜和片尾；以正常播放器尺寸检查可读性，并放大检查容易混淆的字形。
- 比较同一静态镜头前后两个时间点，确认没有意外推近或位移；看配图字幕交界处是否有遮挡、裁切。
- 检查关键金额对应音频及字幕、完整媒体解码、音视频时长和声道。做过的检查写入 `verification.json`，未做过的不标通过。
- 确认版使用明确的文件名并记录哈希。之后的新版本另存，保留已确认成片和原始素材。

原始图片和配音固定后，可以重复渲染同一内容；重新调用图像或 TTS 模型通常不能保证逐像素或逐采样一致。长期复刻必须保存素材，不能只保存提示词。
